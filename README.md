# FileHub Windows 0.3.1

导入你或外部 AI 编写的 JSON 规则文件，在本机绑定文件夹，先预览再执行；支持移动、复制、重命名、子文件夹和 JPEG／PNG／WebP 转换，在记录中查看与撤销。

安装包、离线指南和校验文件见 [0.3.1 版本页面](https://github.com/Wanrd0Geri/filehub-windows/releases/tag/v0.3.1)，需仓库访问权限。下载 `FileHub-0.3.1-windows-x64-setup.exe`，先从托盘退出旧 FileHub，再运行安装包并保留或勾选“添加当前用户右键”；无需重写已有规则。校验文件应与同版本 `SHA256SUMS.txt` 一致。

0.3.1 已通过本地完整测试 **859 项**、实际 EXE 隔离自检 **35/35 项**，独立核对 **56 个打包模块**及 **29 项指南检查**。交付目录为 `F:/FileHub交付/0.3.1/`；文件哈希、构建源码与验证时序见 [0.3.1 交付说明](docs/交付说明-0.3.1.md)。

## 开始使用

1. 打开 FileHub。首次启动自动处理保持暂停，规则文件目录为空。独立图片转换与历史记录无需安装规则。
2. 在“规则文件”打开 [AI规则编写指南](docs/AI规则编写指南.md)，交给外部 AI，并说明自己的处理需求。保存返回的纯 UTF-8 JSON，再导入 FileHub。无需 GitHub、AI API Key 或联网服务。
3. 选择所需本机目录绑定。绑定不会添加观察目录，也不会启用规则。导入、替换、恢复与旧定义迁移后的规则默认关闭。
4. 在“文件处理”选择文件或文件夹，或拖入文件。查看匹配、动作顺序和最终目标，再点击“开始处理”。没有匹配规则时不操作文件。
5. 要自动处理时，另外在设置中明确添加观察目录，在规则文件中启用规则，然后继续整理。自动处理按规则文件优先顺序和文件内规则顺序选第一条匹配规则，不递归扩大 scope，也不回退到旧收件箱行为。

主界面只有“文件处理、规则文件、图片转换、记录、设置”。应用不提供规则或项目模板编写器。修改 JSON 后，使用“替换”或从原来源重新载入；先核对差异，再重新绑定/启用。保留文件 id 与未删除的 rule id。

“手动标签”就是原来的项目代码/目的地输入与最近口令：已有项目配置时，Explorer 右键多选直接打开标签窗口。旧定义尚未迁移或手动权限未授权时，在同一个窗口点击“恢复手动标签归档”并确认一次，然后预览和归档；已输入内容与历史标签保留。多个项目方案需要明确选择。恢复仅新增手动权限；自动规则、观察目录、暂停设置不会因此启用。通用按规则处理仍可从主界面的“文件处理”使用。

个人项目归档使用可选的 `filehub.archive.v1` 完整档案。未匹配进入收件箱、清理各自需要独立授权；文件夹变化不会被隐式发现。正常启动及安装器不提供演示入口；`--demo` 只供隔离工程验收。

## 保护与限制

图片转换默认另存保留原图。明确选择“原地替换（可撤销）”后保存原图备份，支持同格式压缩和跨格式替换；备份不会自动清理，需预留空间。同名目标续接现有末尾版本号，预览固定最终名字；源文件变化、后来占用目标或规则权限变化时停止并要求重新预览。支持 JPEG／PNG／WebP 静态图片，不支持视频转换、动画图、RAW／HDR、OCR、脚本或完整元数据保真。

关闭主窗口继续在托盘运行。升级或卸载前，从托盘退出并等待工作完成。安装器按当前用户安装，不自动启动应用，不删除设置、规则、队列、操作历史或用户素材。Windows 10 22H2 x64 及以上为安装器目标；本轮没有真实安装。Windows 10、新虚拟机、实际安装/升级/降级/卸载、Mac 与真实双机同步未验证。
