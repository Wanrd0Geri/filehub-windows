# 开发与恢复备份

## 备份范围

GitHub 仓库为 `Wanrd0Geri/filehub-windows`，默认分支为 `main`，目前设为私有。仓库保存 FileHub Windows 的源码、测试、构建脚本、需求参考、许可材料和提交历史；Releases 保存对应版本的安装包、中文安装说明与 SHA256 校验文件。

`reference/` 及部分历史记录包含个人目录和原始需求资料。以后若需要公开源码，应先整理适合公开的内容和历史；单独删除当前文件不会删除 Git 历史中的副本。

这份备份不包含用户素材、实际项目文件、本机规则目录册、设置和撤销历史。普通安装的状态默认位于 `%LOCALAPPDATA%\FileHub`；通过 `--state-dir` 启动时使用指定目录。需要备份这些状态时，应先等任务完成并从托盘退出 FileHub，再将整个状态目录另存到私人备份位置，保留 `rule-catalog.json`、目录册备份、内部数据库、队列和转换备份；素材及项目目录另行备份。不要在应用运行中只复制数据库的一部分。

0.3.0 导出的 JSON 规则文件只含可移植定义，不含本机路径、启用状态、观察授权、操作历史或可执行作业。可另存导出文件用于外部 AI 编辑和迁移；换电脑后重新绑定路径、配置观察目录并明确启用。目录册定义恢复不会恢复执行作业。独立 `FileHub-rule-guide-v1.zip` 含离线指南、schema、五份示例与 manifest，无需私有仓库或 AI API Key 使用；它不备份个人规则，示例也不会自动启用。

## 只想安装使用

1. 本地已验证的 0.3.0 安装器和离线指南位于 `F:/FileHub交付/0.3.0/`，大小与 SHA256 见 [交付说明](交付说明-0.3.0.md)。
2. 用有仓库访问权限的账号打开 [0.3.0 版本页面](https://github.com/Wanrd0Geri/filehub-windows/releases/tag/v0.3.0)，在 Assets 下载 `FileHub-0.3.0-windows-x64-setup.exe`、`FileHub-rule-guide-v1.zip` 与校验文件。
3. 从托盘退出旧 FileHub，再运行安装包。无需安装 Python；无需先卸载旧版。
4. 可用 PowerShell 的 `Get-FileHash -Algorithm SHA256` 检查文件，结果应与交付说明或同版本 `SHA256SUMS.txt` 一致。

GitHub 自动提供的 `Source code` ZIP/TAR 是源代码，不是安装包。

## 恢复源码与开发环境

下列命令供开发者或协助维护的 AI 使用，不是普通安装步骤。在 Windows x64 上安装 Git 与 Python **3.12.10 x64**，使用已获仓库访问权限的账号克隆：

```powershell
git clone https://github.com/Wanrd0Geri/filehub-windows.git
Set-Location filehub-windows
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install -r packaging/build-requirements.txt
& .\.venv\Scripts\python.exe -m pip install -e '.[dev]'
```

普通开发所需依赖定义在 `pyproject.toml`；打包使用 `packaging/build-requirements.txt` 和 `third_party/components.json` 固定的版本。`py -3.12` 仅选择 Python 的次版本，请确认它实际指向 3.12.10；打包输入校验会拒绝其他补丁版本。

运行测试使用仓库内新建的隔离目录，明确源码路径并禁止 bytecode：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
$env:PYTHONDONTWRITEBYTECODE = '1'
$taskTestDir = 'sandbox/test-' + [guid]::NewGuid().ToString('N')
& .\.venv\Scripts\python.exe -B -X utf8 -m pytest -q --basetemp $taskTestDir
```

需要工程验收界面时，可明确使用隔离演示状态；正常用户入口不提供演示按钮或快捷方式：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
& .\.venv\Scripts\python.exe -B -X utf8 -m filehub --demo --state-dir sandbox/development-demo
```

## 重新生成安装包

源码中的 ffprobe 和 WebP 插件已固定版本，并保留相应构建配方。三个较大的上游源码 ZIP 不放入 Git，构建前通过现有脚本下载并核对 SHA256；已交付安装包也在 `_internal/third_party/sources` 中保留这三个归档，可离线复制回 `sandbox/vendor-downloads/`。QtImageFormats 对应源码已在仓库的 `third_party/conversion/sources/` 中。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File packaging/prepare-sources.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File packaging/prepare-tools.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File packaging/build.ps1
```

这里的执行策略只对各次 PowerShell 进程生效。`prepare-tools.ps1` 将固定版本构建工具解包到仓库的 `sandbox/`，不进行系统级安装。构建前会检查依赖、第三方许可和源码归档的版本及哈希；若检查失败，应修复明确报告的不一致，保留校验流程。

输出安装器位于 `dist/installer/`；便携程序是整个 `dist/FileHub/` 文件夹，不能只复制其中的 EXE。构建同时生成独立 `dist/FileHub-rule-guide-v1.zip` 与本轮 `dist/artifacts.json`。模块/Help 清单为 `packaging/runtime-inventory.json`；Help及示例不会被自动导入、启用。编译环境发生变化时，不保证重新生成的安装包与历史安装包逐字节一致。
