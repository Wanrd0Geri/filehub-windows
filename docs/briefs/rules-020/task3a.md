Implementation requirements:

- Replace internal backup only checked state/conversion-backups/operationUUID/original filename; cannot be supplied through config. Byte/ADS/time-complete verified durable backup precedes source mutation. Never broaden public engine state-dir operations for this private capability.
- Replace cross-extension publishes verified new file then removes guarded source only after backup/output checks. Same path (including case aliases) renames original handle to owned sibling swap, atomically publishes new output into vacated path, verifies before swap cleanup. Avoid closing source_guard then later blindly deleting a reused path. Cancel before critical phase aborts unchanged; inside critical phase settle restore/commit safely before returning cancellation.
- Failure/recovery restores only exact owned source/swap/backup into unoccupied path. If external file occupies it or ownership unclear, retain all copies and report actionable backup/swap location; no blanket overwrite/cleanup. Backups are retained, no auto-expiry feature.
- Undo keep checks unchanged original survivor and output, with distinct content expected. Undo replace checks backup/output, restores original (cross-ext original path must be vacant; same-path guarded exchange), then removes generated output. Edited files/occupied inverse paths/missing backup produce conflict, never destructive best-effort.
- General file inverse lineage needed for ordered move/copy/convert chains must be persisted from verified inverse operations only (existing tree_lineage pattern). Never accept arbitrary same hash as an ownership substitute. Existing file IDs change when move undo re-creates a prior output; map that restoration to previous operation so correct chain undo works.
- New methods keep encoding out of engine lock (already generated on entry); only guarded publication/backup/state transitions. All OS mutation through existing platform wrappers/checkpoints. No actual user data.
