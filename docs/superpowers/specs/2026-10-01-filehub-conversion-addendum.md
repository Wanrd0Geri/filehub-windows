## Deliverable matrix

Images: input and output JPEG/JPG, PNG, WebP using Qt image readers/writers if actual runtime and packaged plugins prove support. Explicit rejection for unsupported input, animated/multipage assets, extreme allocation, undecodable/corrupt media; do not silently flatten animation or promise RAW/HDR/pro color workflows. Default preserves pixel dimensions, applies orientation deliberately, and retains original. JPEG quality preset (good default 90), transparent→JPEG background choice white/black/custom; PNG lossless, WebP quality/lossless simple choice. Clearly document metadata may not be retained, and do not claim archival metadata fidelity. Re-read generated image to verify dimensions/type; original fingerprint unchanged.

Videos: accept decodable MP4/MOV/MKV/WebM with one supported ordinary video stream and optional audio; output MP4/H.264 + AAC, default original dimensions/frame-rate, no automatic resize. CPU software encoder required. Root proved existing LGPL candidate has libopenh264+aac and produced genuine H264+AAC smoke. If source is already compatible H264/AAC and ordinary MP4-compatible stream properties, remux is available as a clear lossless-fast preset; default compatibility preset may re-encode. Unsupported HDR/high bit depth/interlaced/alpha/unsupported audio or exotic stream layouts must be detected and clearly rejected or explicitly documented supported normalization, never silently claim preservation. Preserve source frame rate including ordinary VFR by avoiding forced -r; validate output dimensions/streams/duration tolerance. Progress, per-item status, cancellation, batch continuation after one failure. No user tool install or network needed after application installation.

Backend dependency: use Qt existing runtime for images; packaged WebP plugin requires QtImageFormats/libwebp corresponding license/source materials. Prefer minimal FFmpeg+OpenH264 CPU build with existing pinned FFmpeg source and compatible LGPL/BSD components, no broad static third-party binary bundle. All source/version/hash/configure/patch/license records included. Root prototype at `sandbox/root-media-probe` is read-only evidence only and must not become delivery. Existing compiler/tool files under F checkout can be invoked read-only; build/download outputs only in new sandbox. No pip writes to shared .venv.

## Data safety and architecture

Add focused `conversion/` models, image/video backend, facade/staging modules. Staging happens at an exclusively created owned hidden sibling path (not final filename) with source guarded/fingerprint-bound, timeout/cancel, validation, and cleanup only exact owned staging paths. Final output conflict never overwrites. Publication is through an explicit engine generated-output path, not pretending original and converted bytes are equal. Planned conversions bind input fingerprint, settings, codec capability and exact target. Default preserves originals; no delete-original toggle in 0.2.0.

Task3 will add narrow `OperationEngine.publish_generated(source, target, expected_source, staging, expected_output, label, batch_id=None)` and explicit journal `convert` semantics, with safe old-journal schema migration. Ordinary engine.execute must not interpret convert as a normal copy. Journal records original source fingerprint plus output fingerprint; forward publication validates original unchanged and generated output then atomically renames held staging without replacing an occupied target. Durable intent before publication; uncertain recovery reports conflict and does not replay encoder. Undo conversion removes/recycles only an unchanged owned output while verifying original source remains unchanged (different content is expected); if original missing/changed or target changed, preserve and report conflict. Cancellation before publish produces no success record/final file. Rule conversion changes subject to output; later copy/move/rename sees its new fingerprint. Rule reverse chain must restore generated output before conversion undo. Batch history labels conversion explicitly and shows input/output format. Source→converted output lineage is distinct from byte-preserving copy.

Media core agent initially owns only backend staging generation/validation and dependency preparation, not engine/journal/rule/UI. It exposes ConversionSpec, capability matrix, plan validation, and `generate(source, staging, spec, cancel_event, progress) -> validated metadata`; no final publication and no automatic real-folder scan. Runtime integration consumes this after task boundaries reviewed.

UI: separate “转换” page with image/video preset selector, file batch selection, output folder, keep-original note, preview planned filenames, Start/Cancel, per-item progress/results. Rule action editor adds image_convert/video_convert with same presets; action order text states output becomes subject. GUI thread only signals. A dedicated conversion executor with max_workers=1 runs encoding and conversion-bearing rule chains; the existing Coordinator continues ordinary archive/settings work. Long decode/encode never holds the global engine process lock. Claim, publication and progress/state transitions acquire that lock only for short mutation boundaries; guarded input/fingerprint checks and exclusive target publication reject conflicting work. Scheduler claims and enqueues a conversion rule then returns promptly; queued work revalidates rule/template/source/targets before mutation. Completion reports refresh history via GUI-safe callbacks. Cancel reaches a thread-safe event directly, never a blocked queue; demo switch/service replacement invalidates callbacks and cancels obsolete conversion jobs. Shutdown stops accepting work and cancels/joins owned jobs conservatively. No generic multi-job parallel scheduler is required. Demo isolated, settings/history reflect state.

Acceptance: real image transparency/orientation/size and output codec verification; video MP4/MOV/MKV/WebM fixtures, remux and CPU encode with audio/video, malformed/unsupported cases, cancel mid-encode, collision and original-fingerprint preservation; journal migration/publication crash/undo conflicts; rule convert→move/rename chain and restart suppression; packaged native plugin/encoder smoke with no developer PATH. One final combined gate and installer, no live installation or user-state changes.
