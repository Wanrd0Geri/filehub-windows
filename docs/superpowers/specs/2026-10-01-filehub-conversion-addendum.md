# Image conversion scope — current user-authorized 0.2.0 goal

Current binding scope: user said “视频转换功能就先不加了。其他的加上”. Deliver templates + practical automation rules + IMAGE conversion (standalone page and rule action) + reviewed installer. Video conversion/encoding, video conversion UI/action, new FFmpeg encoder/OpenH264 dependencies are excluded. Existing video archive/probe behavior remains unchanged. Earlier full-media authorization is historical and superseded. This document supersedes its previous video-inclusive edition. Root baseline/live-user safety constraints remain.

## Image support matrix

JPEG/JPG, PNG, WebP input and output using Qt image readers/writers, gated on actual runtime and packaged plugin support. Reject unsupported formats, animated/multipage images, excessive allocation and corrupt media explicitly; never silently flatten animation. Default preserves pixel dimensions and applies orientation deliberately. Two integration modes are required: preserve-original save-as, and true in-place replacement with durable backup and undo; see replacement contract below. JPEG quality defaults 90; transparency→JPEG background white/black/custom. PNG lossless; WebP quality/lossless choice. Metadata may not be retained; state this without promising archival metadata fidelity, RAW/HDR or professional color workflows. Re-read output to verify dimensions/format; verify original fingerprint unchanged. Limits and allocation failures produce clear messages.

Qt is existing runtime. WebP plugin requires corresponding QtImageFormats/libwebp source/license materials matching actual shipped plugin version. Verify actual binary/runtime version; do not assume declaration alone. No pip changes to shared .venv. No new encoder or OpenH264 binary/material in final payload. Existing ffprobe unchanged. Prior video diagnostics, if any, remain ignored sandbox data only.

## Backend and safety

Focused conversion/models.py, images.py and facade/staging helpers. Backend API: image-only ConversionSpec(output_format='jpeg'|'png'|'webp', quality=90, background='#FFFFFF', lossless=False, max_pixels=bounded limit); capabilities returns actual Qt reader/writer support; inspect/validate binds input fingerprint/properties/options. `generate(source, staging, spec, cancel_event, progress) -> ConversionResult` returns verified source/output fingerprints, dimensions and warnings. Staging path must be caller-specified, nonexistent, exclusively created and exactly owned; backend never publishes to a final user filename.

Publication integrates through explicit engine generated-output semantics, not byte-preserving-copy fiction. Plans bind input fingerprint, options and exact final path. Keep mode retains originals. Replace mode is explicitly selected and removes the original only through the backed-up transaction below; it is not same-directory save-as. Unrelated conflicts never overwrite. Task3 adds narrow `OperationEngine.publish_generated(source, target, expected_source, staging, expected_output, label, batch_id=None)` and explicit journal `convert` semantics with safe old-journal migration. Journal tracks original/source and generated/output fingerprints. Verify unchanged guarded original plus validated generated artifact, then atomically publish without replacing occupied destination. Durable intent precedes publication; interrupted/uncertain states are classified without automatic reconversion. Cleanup removes only exact owned temporary artifacts; cancellation/failure leaves no completed-looking final file.

Undo conversion only removes/recycles the unchanged owned generated output while verifying original is still unchanged; unlike copy, bytes intentionally differ. If original is missing/changed or output edited, preserve output and explain conflict. Rule image_convert produces a new subject; subsequent rename/move/copy uses its generated fingerprint. Reverse chain restores generated subject before conversion undo, with verified inverse lineage rather than weakened arbitrary fingerprint checks. History labels conversion explicitly and shows format change.

## Responsive execution and UI

One dedicated image conversion executor (max_workers=1). Decode/encode never holds global process lock; short claim/publication/ledger transitions use existing lock. The ordinary Coordinator continues archive/settings work. Conversion-bearing rule chains use the conversion executor; scheduler claims/enqueues and returns promptly. Queued jobs revalidate rule/template/source/target snapshots. Thread-safe cancellation bypasses the worker queue; checks occur between image decode/encode/validation/publication and between items. A currently running Qt codec call may finish before cancellation is observed; no output is published after cancellation. Demo/service replacement cancels obsolete jobs and invalidates callbacks. Shutdown stops submissions and conservatively joins owned jobs.

Separate “图片转换” page: image format/quality/background preset controls, select batch, output folder, keep-original note, planned filenames, Start/Cancel and per-item progress/results. No video options. Rule action editor offers image_convert with same controls, and explains output becomes the subject. No required JSON editing. Small-window forms scroll; all filesystem work off GUI thread. Errors are per-item, remaining batch items can continue; cancellation stops remaining items.

## Acceptance

Real JPEG/PNG/WebP decode/encode; transparency background; orientation/dimensions; animated/corrupt/unsupported/large input rejection; cancellation before publication; conflict/no-overwrite; original preservation; explicit journal migration/publication crash/undo conflict; image-convert→rename/move/copy chains and persistent run suppression; independent queue responsiveness; packaged WebP plugin real roundtrip without developer PATH. Final combined source gate and installer, no live user installation or state changes.

## Required true in-place replacement contract

User explicitly requires real replacement, not merely another format beside the original. Both standalone page and image_convert rule action expose mode=keep|replace. Keep is conservative default; replace is clearly selectable without output-folder setup. Cross-extension example `a.webp → a.png`: success leaves a.png in the original parent and removes a.webp after backup/publication verification. Same-extension recompression `a.jpg → a.jpg` is also supported. Preview states replacement, exact final path/new extension, and recoverable original backup. No unrelated existing target or other selected source may be overwritten; same-path exception is limited to this transaction's fingerprint-bound original. Case-insensitive Windows path comparison applies.

Internal backup path is generated only by trusted code under checked state_dir/conversion-backups/<operation UUID>/, never accepted from rule/import/UI data. Backup preserves original full bytes, named streams and source timestamps via existing guarded engine primitives; record its fingerprint and location durably. No automatic backup cleanup/retention policy this release. Backup failure aborts before source mutation. Backups and output must remain distinguishable in journal; history shows actionable backup path on unresolved recovery.

Encode/validate first in exclusively owned sibling staging, then create and verify durable backup. Cross-extension: publish output without overwrite while original survives, verify output+backup, then remove bound original with durable intent. Same path: after verified backup, journal intent then rename the held original to an owned hidden sibling swap path, publish generated staging exclusively into vacated original name, verify before removing original swap. Ordinary failure safely restores original if path is unoccupied; never replace an external file that raced into it. Cancellation checked before transition and rollback path; once critical publication starts, finish/rollback safely before returning cancellation result.

Crash recovery never re-encodes or blindly retries. At each durable state, inspect exact original/swap/output/backup fingerprints. Restore the original from owned swap/backup only when its intended path is free and ownership/progress evidence is conclusive. Otherwise preserve all recoverable objects, mark conflict and display backup/swap locations. Never label partial replacement success.

Undo verifies unchanged owned output and intact original backup. Cross-extension restores original path (must be free) before removing generated output. Same-extension uses guarded swap/publication to restore original without overwriting an unrelated changed file. Edited output, missing/changed backup, occupied original path or uncertain lineage preserve data and report conflict. For a rule chain, later inverse operations restore generated subject first; then replacement undo restores original from backup. Keep-mode undo continues to require the untouched original survivor.

Required focused tests: keep vs replace; cross-ext and same-path/case variants; unrelated occupied target and selected-input overlap; backup write/full-stream verification failure; cancel before codec/backup/publication and during critical boundary; injected crash checkpoints around backup, source swap, output publish and source removal with fresh-process recovery; undo after later rename/move, edited output, missing backup and occupied source. All owned sandbox only.
