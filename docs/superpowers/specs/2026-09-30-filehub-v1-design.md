## 目标与已确认的界面

面向没有编程经验的日常使用者。文件先放桌面或下载文件夹，需要时通过右键输入项目代码，自动完成命名与归档；闲置文件按规则进入收件箱。

最终交付中文 Windows 安装程序、卸载入口和使用说明。用户不需要自行安装 Python 或修改配置文件。

界面采用已确认的侧栏工作台：默认深色，炭黑与深灰分层、暖黄色图标、紧凑间距、10px 主窗口圆角。保留整理、收件箱、记录、设置四个入口；右键归档使用小窗口。支持浅色与跟随系统。

## 第一阶段：可以双击运行的测试版

首先打通一条完整流程：选择测试文件 → 输入代码 → 预览新名称和目标位置 → 执行归档 → 查看记录 → 撤销。

- 支持项目自动识别，以及镜头、角色、场景、道具、PV、成片和保留原名目录的路由。
- 保留现有命名规范，支持视频分辨率识别、版本递增、合镜复制和内容查重。
- 支持文件多选；同一批共用一个输入代码。需要不同代码的文件分批处理。
- 错误代码、缺少镜号、目录不可访问或视频信息读取失败时，保留源文件并给出中文原因。
- 使用工作目录内的假同步空间与样例文件，默认不接入真实桌面、下载目录和项目。
- 用测试入口模拟右键传入文件；真正注册资源管理器右键菜单放在安装验证阶段。

第一阶段交付可运行的测试程序，不把 HTML 预览当作完成的软件。

## 第二阶段：后台整理与 Windows 集成

- 提供右键「送进项目…」入口，支持多选。Windows 11 的首版入口可位于「显示更多选项」。
- 提供托盘图标、暂停/恢复、目录选择、整理天数设置和操作记录。
- 登录后运行，定期检查；计算机休眠或关机期间不承诺按时执行，恢复运行后重新检查到期情况。
- Windows 默认关闭共享收件箱到期清理和同步空间全局改名，由 Mac 统一负责。
- 桌面和下载使用系统真实位置；首次接入时展示管理范围并给已有文件缓冲期。
- 不自动移动项目中的既有文件，不新增通用规则编辑器。

## 必须落实的文件保护

- 本机整理任务与手动归档统一排队，目标文件不得被覆盖；版本分配和实际写入需要一起防止并发冲突。
- 检查下载临时文件、文件占用和写入状态；仍在变化的文件稍后重试。跨磁盘移动先完成复制与校验，再处理源文件。
- 记录文件首次进入受管理目录的时间，避免旧文件刚移到桌面就被判定为到期。记录库位于本机应用数据目录，不依赖网盘同步。
- 删除进入 Windows 回收站；回收站操作失败时停止该项操作，不降级为永久删除。
- 按批次记录操作类型、源路径、目标路径和可核对的文件身份。移动、改名、合镜复制分别设计撤销逻辑。
- 撤销时若文件已被编辑、原位置被占用或回收站内容已清空，保留现状并解释限制，不强行覆盖。
- 不把百度网盘当作跨电脑的实时锁。首版以同一镜头避免双机同时命名为使用约束；若必须支持双机任意同时编号，需要额外的统一编号服务。

## 对照原脚本时需要明确修正的差异

以下为建议修正项，需要与用户确认的规则基线一致；不能同时宣称逐字照搬脚本和改变其实际行为。

1. 正片/PV 标签里的镜号目前可能在命名时丢失，应按说明中的预期保留。
2. 合镜副本目前不能完整撤销，应补齐按操作类型撤销。
3. 原脚本截断超过 150 字符的文件名，与需求文档不一致。建议保留可用名称；超出系统或组件限制时提示，不静默截断。
4. 时间与命名分离：在操作前固定本次使用的源时间；跨平台对照使用相同时间、时区与已有版本数据，不能只比较同步后各自的创建时间。
5. 全局任务开关、Windows 回收站和防占用检查属于需要新增的平台能力。

## 实现方案建议

优先考虑 Python 共用规则核心 + PySide6/QML 桌面界面，再打包成 Windows 程序。该方案便于复用原脚本，提供托盘和本地文件操作，并实现已选的自定义界面。

另外两条可行路线是网页界面配 Python 后端（更容易复用预览样式，但需要处理浏览器运行组件）以及纯 Windows 原生实现（系统集成直接，但原 Python 规则需要更多重写）。建议优先保留 Python 核心，把平台接口与界面分开。

核心划分为：规则解析与命名、Windows 平台适配、文件操作与日志、后台调度、桌面界面。字体和视频检测工具在正式打包时核对许可证并准备随包分发方案，保证安装后的常用流程可离线使用。

Mac 现有程序继续使用原版本；后续若将其切换到共用核心，单独验证后再替换。
