# FileHub Windows 0.3.1 使用说明

FileHub 负责校验、绑定、预览、执行与记录。规则文件由你或外部 AI 编写，应用不内置普通情景库，不提供条件/动作或项目模板编写器。安装包、离线指南和校验文件见 [0.3.1 版本页面](https://github.com/Wanrd0Geri/filehub-windows/releases/tag/v0.3.1)，需仓库访问权限。下载 `FileHub-0.3.1-windows-x64-setup.exe`，从托盘退出旧程序后运行安装包；已有规则无需重写。

## 规则文件

在“规则文件”打开“AI规则编写指南”，把指南及具体需求交给外部 AI。指南、JSON Schema 和五份完整示例可离线使用，也可作为独立 `FileHub-rule-guide-v1.zip` 分享；示例不会自动导入或启用。保存纯 UTF-8 JSON，顶层 `format` 为 `filehub.rules`，`version` 是整数 1。应用不调用 AI 服务，也不需要 API Key。

点击导入，应用通过与命令行相同的严格解析器拒绝未知字段、重复键、错误类型、未知版本、非法路径及动作。单文件最多 2,000,000 字节；最多安装 100 个文件、1000 条规则。本机目录册最多 16,000,000 字节。具体有限条件、命名 token 和动作格式见 [完整指南](AI规则编写指南.md)。

规则通过符号 binding 声明文件夹，在本机用“绑定目录”选择真实路径。禁止状态目录重叠、链接/junction、路径逃逸、ADS 和非法 Windows 名称。绑定不创建目录、不添加观察目录、不授予自动处理权限。未使用的声明可以留空；实际使用的目录未绑定时对应规则不可用。

导入后规则停用，选择停用规则仍可明确手动预览。修改文件时保留 package id 与已有 rule id。通过“替换”选择新文件，或明确从来源重新载入，先核对新增、改变、移除的规则及绑定差异。替换和恢复后规则全部关闭，兼容权限清空；不要假设先前自动授权会保留。

导出只含可移植定义，不含本机路径、启用状态、观察授权、任务或历史。文件顺序可调整；移除只移除定义，不删除用户文件。目录册每次成功更新保留经验证的定义备份；恢复需明确选择备份，恢复定义不会恢复可执行作业。目录册损坏或缺失时停止使用规则并提示显式恢复，不静默回退旧定义。

## 手动文件处理

在“文件处理”选择文件或文件夹，或拖入文件。默认匹配已启用规则，也可显式指定某条停用规则。Explorer 的“用 FileHub 处理…”多选入口在已有项目归档配置时直达“手动标签”；没有项目归档方案时打开通用规则窗口。

先预览来源、匹配原因、有序动作与目标；确认后点击“开始处理”。规则可移动、复制、重命名、放入子文件夹或转换图片。动作严格按顺序执行，复制后的后续动作针对复制出的对象。目录与文件都受指纹、目标占用和状态隔离保护。预览后修改定义、绑定、配置或来源时，旧预览失效。

非空 scope 只允许来源处于列出目录的顶层，手动也不例外；文件夹本身可以作为顶层对象处理。空 scope 表示自动限于已配置观察目录，手动可以选取文件。没有匹配规则时显示原因，不会偷偷套用旧项目口令或把文件送入收件箱。

执行结果在“记录”中查看。取消会停止尚未开始的项；正在发布或替换时先安全完成或恢复。成功写入的批次可以撤销；原位置后来被占用、文件变化或备份不一致时，撤销可能要求核对，不能假设会覆盖后来修改。

## 自动处理

分别完成三个授权：在设置中添加独立观察目录，在规则文件中启用规则，再从暂停切换到继续整理。绑定路径不是观察授权。观察目录不允许磁盘根或与应用状态重叠；只有明确启用兼容档案时，另外检查该档案的实际保护路径与清理范围。未启用的历史同步根设置不会阻断普通规则。首次启动保持暂停。

应用运行时约每 10 分钟检查明确选择的观察目录，按规则文件优先顺序、文件内规则顺序选择第一条匹配规则。scope 可以声明 A、B，而只授权观察 A；B 仅能手动处理。不会递归扩大来源；已经处理、被领取、失败或未匹配时不转交后续规则或旧整理器。启用含个人项目动作的规则另外要求对应兼容档案授权。

## 图片转换

“图片转换”独立使用，无需规则、同步根或项目口令。支持 JPEG／PNG／WebP 静态图片，保持像素尺寸，最多 4000 万像素。可调整有损质量、WebP 无损和 JPEG 透明背景色。拍摄日期、色彩信息等元数据可能丢失；不支持视频转换、动画图片、RAW／HDR、网络、OCR 或脚本。

默认“保留原图另存”；明确选择输出目录并预览。原地替换支持同格式压缩及跨扩展名转换，发布前保存完整可恢复备份，记录原图字节、命名数据流和时间。备份不会自动清理，需预留磁盘空间。

已有 `图片-6.jpg`、`图片-9.jpg` 时，新目标续接为 `图片-10.jpg`，不会叠加 `-1`。预览固定实际目标；执行时后来占用该目标或来源变化，停止并要求重新预览。相同路径替换只有明确选择替换模式才允许；不同路径不覆盖现有文件。

## 可选个人项目归档与旧定义迁移

“手动标签”保留原来的项目代码/目的地输入、最近口令复用、单条删除与清空全部。已有配置时，右键多选文件直接打开此窗口；已授权用户可直接预览目的地并“送进项目”。通用按规则处理始终可从主界面“文件处理”进入。

若检测到原来的项目设置尚未迁移，或已有方案尚未授权手动归档，窗口显示“恢复手动标签归档”。确认一次后，在同一窗口继续预览；输入、文件选择和历史保留。仅预览或取消不会迁移/授权。旧定义保留，导入的自动规则保持关闭，暂停状态、全局任务、观察目录不变。同一已选方案只新增手动权限并保留原已授权权限；切换方案需确认旧→新及原方案项目规则关闭的影响，新方案仅授权手动标签。多个方案必须自行选择。

只有规则文件完整声明 `filehub.archive.v1` 兼容档案、绑定根/项目等目录，并明确选择档案与授权后才可使用。手动归档、未匹配进入收件箱、清理是三个独立权限。默认均关闭；正常空规则目录不保留旧整理行为。

兼容档案记录项目代码、项目目录、模板及口令路由。它是显式快照，新增或改变项目目录不会被自动发现。修改这类行为应由外部编辑完整 JSON，替换后重新核对并授权。它不是应用内普通情景库。

检测到旧配置、规则或模板时，不自动激活。“规则文件”页的“迁移旧设置”只导入定义：确认来源及定义后，原旧文件保留，规则关闭且兼容权限为空；需要另外选择绑定、启用和权限。“手动标签”窗口的一次恢复则导入所需旧定义并新增手动标签权限，自动规则保持关闭。迁移及定义恢复不重建可执行队列或作业。

## 托盘、安装与隔离工程验收

关闭主窗口后继续在托盘运行。退出时从托盘选择“退出 FileHub”，等待工作安全结束。升级/卸载前同样先退出。安装器按当前用户安装，无需额外 Python/ffprobe，不自动启动应用，不删除个人素材、状态、规则、队列、记录或转换备份；Explorer/开机启动项仅操作应用拥有的注册项。

正常开始菜单只有 FileHub，无演示快捷方式。`--demo` 和 `--self-test --state-dir <独立目录>` 是显式工程验收入口，不应指定真实用户状态。自检在所给父目录下新建 UUID 子目录，保留实际执行证据；不会安装软件或修改实时注册项。便携使用必须保留整个 FileHub 文件夹，不能只复制 EXE。

Windows 10 22H2 x64 及以上为安装器目标。历史 0.3.0 的独立验证结果见 [0.3.0 交付说明](交付说明-0.3.0.md)，仅适用于该历史版本。Windows 10、新虚拟机、实际安装/升级/降级/卸载、Mac 与真实双机同步未验证。
