## Public interfaces for Task 5

Existing engine/service signatures remain compatible. `Fingerprint.capture(path)` now returns an ordinary `Fingerprint` or its frozen `TreeFingerprint` subclass. `TreeFingerprint` adds `entries: tuple[(relative_name: str, Fingerprint), ...]` and `directories: tuple[DirectoryIdentity, ...]`; `DirectoryIdentity(name, device, file_id, creation_ns, mtime_ns)` includes root name `.`. Typed journal roundtrip is via existing `Fingerprint.from_dict` dispatch. Directory ADS are explicitly refused; file ADS and exact creation/mtime remain supported through Task1's original primitives.

`ItemResult` gains defaulted `parent_operation_id: str|None=None`. UI/history count rows with `parent_operation_id is None` as top-level operations and expose child details under the matching root. Root tree conflict is not success even when some child operations committed. Children retain their exact staged/final locations and states after restart; the controller must not infer group membership from path names or SQL.

- `Scheduler(service).tick(now: aware datetime)->list[BatchResult]`; naive/non-datetime timestamps reject. Tick date uses the provided timestamp's timezone. `TICK_INTERVAL_SECONDS=600`; UI supplies an awake-app timer and owns pause/settings persistence. Each tick reads current `service.config`. `Scheduler.last_errors: tuple[str,...]` exposes conservative skips/scan errors. Scheduler construction only initializes local observation state.
- `SendQueue(state_dir).enqueue(paths, *, now=None)->str` durably stores absolute paths and returns a request ID. Each secondary process must enqueue before exiting.
- `.claim(*, now=None, settle_seconds=0.3, lease_seconds=30)->SendBatch|None`; claims all pending requests only after the latest has settled, deduplicates paths case-insensitively in selection order, and excludes another active claim. Frozen `SendBatch(token, paths: tuple[Path,...], request_ids: tuple[str,...])` represents one combined selection.
- `.renew(token, *, now=None, lease_seconds=30)->None`; keep a dialog/worker claim alive while it is owned. `.ack(token)->None` durably removes handled requests; stale/reclaimed token raises. `.release(token)->None` returns the selection for later handling. Expired/unacked claims are retried after process crash. GUI must keep the lease until its selection is handled, renew while pending, and acknowledge only completed or explicitly dismissed requests; it must not ack before creating/owning the selection dialog. New arrivals while a claim is active wait for the next combined dialog. UI can poll the queue roughly every 100–250ms; settling is independent from the scheduler's 10-minute timer.
- `InstanceLease(state_dir).try_acquire()->bool`, `.close()->None`; a separate nonblocking Windows byte-range lock selects the primary process, released by close/process exit. Queue operations use the shared engine process lock, never the GUI-instance lock. Secondary enqueue does not require owning the instance lease.
- `parse_runtime_args(argv=None)` supports `--send paths...`, `--background`, `--state-dir Path`, `--self-test`, `--demo`. Parser preserves Unicode/spaces and selected path order. Task5 still supplies the actual CLI/GUI entrypoint and self-test behavior; this stage provides parsing and transport only.
- `known_folders(*, resolver=None)->{'desktop':Path,'downloads':Path}` uses native `SHGetKnownFolderPath` IDs by default; injected resolver receives the GUID. Paths are proposals only and never activated or created by this API.
- `install_context_menu(exe, *, registry=None)`, `remove_context_menu(*, registry=None)`, `set_autostart(exe, enabled, *, registry=None)` use native `HKCURegistry` only when invoked without an adapter. `exe` must be absolute. Injected adapter implements `exists/get/set/delete_value/delete_key_if_empty` on HKCU-relative keys. Tests use an in-memory adapter exclusively.

## Safety and durable accounting

Tree capture refuses any symlink/junction/cloud reparse component, nonordinary file, directory named stream, or unreadable subtree. `os.walk(onerror=raise)` cannot silently omit an unreadable child. Captured source directories are pinned against rename/replacement with Windows backup-semantics handles; newly arriving children are still permitted. Every captured file uses the original operation engine's exclusive staging, full primary/ADS verification, exact metadata copy, no-overwrite publication, strong survivor handover and guarded deletion. Every child operation is durably linked to its root before mutation.

Directories are copied/moved through captured manifests, including empty structure and directory creation/lastwrite times. After file work, only captured directories with matching identity are considered for removal. Directory handle disposition first proves no children or named streams and the OS independently refuses nonempty deletion. There is no recursive deletion or `rmtree`. Source new/changed entries survive; failed children, leftover source entries, and external target arrivals produce root conflict/partial. Staged copies survive crash/failure. Source and child reparse status is rechecked during execution and file guard acquisition, not only preview.

Undo preflights each whole target tree and original root before any child inverse. An unexpectedly recreated empty root or root containing user data refuses the root and every child, including later repeated undo calls. An absent original root is exclusively created and pinned with durable `tree_inverse_roots` directory identities before inverse children begin. A resumed owned inverse root must retain exactly those directory IDs/names and only exact child `undo_fingerprint` entries from already completed inverse operations; external additions, changes and same-byte replacements refuse. `tree_undo_blocks` durably prevents bypassing a previously blocked root by retrying only its children. Legitimate partially completed inverse survives restart/recovery when the remaining targets and restored originals match their precise recorded identities. Whole target changes likewise block every child. Child inverse operations retain ordinary-file survivor protections. Empty-directory restoration and safe target pruning complete the root. A legitimate ancestor inverse creates new file IDs, so nested bottom-up name sanitation needs durable inverse identity lineage: a predecessor can be rebound only if its strict previous target fingerprint appears in that ancestor's original captured manifest; the precise new IDs must match child `undo_fingerprint`, both preserved times/full stream contents match, and strong file/ADS plus directory guards protect the rebind. `tree_lineage` old/new fingerprints and the predecessor update commit in one transaction. Equal-content external replacement before or after capture never qualifies. Crash gaps can safely yield conflicts/manual reconciliation; no broad content-only undo identity exception was introduced.

Whole-directory recycle first moves only captured entries through those same proven primitives into a durable unique sibling tree, preserving empty structure. Inbox day trees use `收件箱_类别_日期.filehub-<id>`. New/changed source arrivals or failed transfers retain original survivors plus reachable staged contents and prevent the native tree recycle call. A complete matching stage is rechecked and then sent once to the injected/native recycle adapter, with root `recycling` intent and exact staging path already durable. Failure keeps that reachable path; missing/unconfirmed stage is `recycle_unknown`. Successful root undo reports one whole-folder name/original path as `manual_restore` and suppresses misleading child auto-restoration. Recovery never continues deletion; a missing stage after interrupted native recycling stays unknown and retains any manual-bin content. Native tree restore is not claimed automatic.

## Scheduler and Windows boundaries

Observation state is local SQLite under the existing engine lock, keyed by path, scope and source identity, with durable first-seen and observed-change timestamps. Idle begins at the latest of first-seen, observed-change, creation/mtime and contained tree activity. Hash/stream or identity changes reset conservatively, even if mtime is restored; disappeared observations are removed. Paused ticks clear observation buffers and mutate no source; resuming unseen inputs begins full grace at observation. Old-mtime arrivals therefore retain the default three-day buffer across restart.

Only explicitly configured top-level watch roots are scanned; state/sync/ancestor/descendant overlap, drive roots and reparse roots reject. Hidden paths, partial-download suffixes, Office lock files, locked/writing files, and owned `.filehub-` staging are skipped. The exact hidden `.baiduyun.uploading.cfg` and suffix-named stable residuals are narrowly eligible for recycle after the same inactivity/first-seen buffer. Folders always go to 其他; file classification uses original extension; date folders use the tick date. No project routing is performed by watch sweeping.

`global_jobs=False` remains the default and means this Windows app does not assume the Mac's shared-job ownership. Explicit enable runs both shared inbox expiry and bottom-up invalid-name sanitation throughout sync, including existing project names. Valid names and asset routing positions stay unchanged; conflicts never overwrite. Each actual name change is journaled and reverse history undo supports nested changes. Hidden/reparse/staging paths are skipped. Inbox day expiry accounts for new contained arrivals/changes and never cleans a still-writing/locked day. The advanced UI must explain both effects and only-one-computer ownership beside its switch in Task5.

Context registration is HKCU `Software\Classes\*\shell\FileHub.Send` and `Directory\shell\FileHub.Send`, with 中文 label `送进项目…`, quoted executable and `--send "%1"`. Owned markers/recorded command protect foreign keys, values and later foreign command modifications; cleanup deletes only owned matching values and empty own keys. Autostart is opt-in HKCU Run `FileHub`, exact quoted installed command ownership, and leaves other/foreign values untouched. No HKLM writes or native scheduled task are required.

`MultiSelectModel=Player` uses the Windows legacy selection model (classic context menu cap **100**); the per-file invocations are accumulated by the durable queue, including more than 15 paths. GUI select/drop can handle larger batches. Reference: https://learn.microsoft.com/en-us/windows/win32/shell/how-to-employ-the-verb-selection-model . Windows 11 may expose this verb under 显示更多选项. Tests prove adapter values, 24-request aggregation, and real three-process delivery; actual Explorer menu/process dispatch, real HKCU install/uninstall, redirected native KnownFolder behavior, native whole-directory recycle/manual restoration, and packaged CLI are deferred to installer/Task6 acceptance.

Cross-volume behavior is tested through the unconditional existing per-file copy/verify/remove path on the sandbox F: filesystem with deterministic faults; no second-volume hardware or real power-loss claim. Directory ACLs inherit the target parent; directory ADS reject rather than silently lose data. App sleep/closure means no timer processing until running/awake, so background scheduling is not a Windows always-running-service promise.
