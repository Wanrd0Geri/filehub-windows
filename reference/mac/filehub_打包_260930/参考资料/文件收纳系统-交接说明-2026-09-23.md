# 文件收纳系统 · 交接说明（2026-09-23）

> 给以后的自己、新对话里的 AI、或帮忙维护的人看。读完这一份就能接手，不用回看原聊天。
> 规则的实现以 `~/script/filehub/filehub.py` 为准；这份说明和脚本不一致时，以脚本为准并更新这份说明。

---

## 一、这套系统在解决什么

- 原来的问题：同步空间文件夹多、使用率低，命名没规律；东西都堆在桌面，时间一长就懒得管。
- 设计原则：
  1. **下载那一刻什么都不用判断**。东西照常先放桌面。
  2. **你只做一件事：能用的文件打一个标签**。改名、放到哪、建文件夹都由脚本完成。
  3. **没人管的文件靠时间自动流走**：桌面放 3 天进收件箱，收件箱放 7 天进废纸篓。
  4. **不提前建空文件夹**，用到了再建。

## 四、命名规则

文件名不带项目代码，因为文件已经在项目文件夹里了。

```
镜头   <集场>_<C镜号>_<段落/备注>_<日期>-<序号>_<分辨率>.ext
       E02S10_C025_白模_260923-2_720p.mp4
       PV_决战_260918-6_1080p.mp4
       正片_C020_260224-6_1080p.mp4
资产   <资产名>_<备注>_<日期>-<序号>.ext
       苏云_法相_260918-1.png
成片   <集>_成片_<日期>-<序号>_<分辨率>.ext
       E01_成片_260922-2_4K.mp4
文档   <集>_<类型>_<日期>-<序号>_<备注>.ext        （迁移时的写法）
       E01_分镜表_260411-2.xlsx
```

- **段落、备注写在日期前面**，这样同一段落排在一起，段落内部按日期先后排（用户要求）。
- **日期-序号**：`260922-2` 表示 2026-09-22 这一场或这个资产当天的第 2 个。日期优先取原文件名里的日期（即梦文件名自带），没有就用文件创建日期。序号由脚本自动数。
- **已经带日期-序号的文件**（比如同一条视频超分后的版本）沿用原来的日期和序号，只补分辨率，所以 `…260922-2_1080p` 和 `…260922-2_4K` 会排在一起。
- **镜号**：一律补零（`C025`），可以不填。
- **分辨率**：只有视频加，按画面宽度分档（因为画幅是 21:9）：小于 1200 为 `480p`，小于 1700 为 `720p`，小于 3000 为 `1080p`，其余为 `4K`。
- **图片**不加分辨率，资产图默认都是超分过的。
- **编号**一律补零：`E02`、`S10`、`C025`。
- **保留原名**的位置：`0_甲方`、`_参考`、`_测试`、`2_剧本分镜`（用标签送进来时）。

## 六、没打标签的文件怎么流走

```
桌面 / 下载
  ├─ 打了路由标签 ─────→ 改名，放进项目
  └─ 3 天没动 ─────────→ 0_收件箱/<图片|视频|其他>/<进收件箱那天>/
                          （~$ 锁文件、.baiduyun 网盘残留直接进废纸篓）
0_收件箱
  ├─ 打了路由标签 ─────→ 改名，放进项目（忘了打标签可以在这里补）
  └─ 日期文件夹满 7 天 ─→ 整个移到废纸篓，改名为「收件箱_视频_260923」，并弹通知
```

- "没动"指创建时间、修改时间、放到这个文件夹的时间三者中最晚的一个。
- 一个文件从放上桌面到进废纸篓，最长大约 10 天。
- 天数在 `~/script/filehub/config.json` 里改：`sweep_days`（默认 3）、`inbox_days`（默认 7）。
- **进废纸篓不是彻底删除**。在废纸篓里按「收件箱_类型_日期」找，右键「放回原处」即可恢复。

## 七、Hazel 配置（Hazel 6.1.2，共 3 个文件夹、4 条规则）

所有判断都在脚本里，Hazel 只负责触发。规则里的脚本都选 **embedded script**，Shell 选 `/bin/zsh`。

| 文件夹 | 规则 | 条件 | 动作 |
|---|---|---|---|
| 桌面 | `filehub` | Passes shell script：`/usr/bin/python3 "$HOME/script/filehub/filehub.py" due "$1"` | Run shell script：`/usr/bin/python3 "$HOME/script/filehub/filehub.py" handle "$1"` |
| 下载 | `filehub` | 同上 | 同上 |
| 同步空间/0_收件箱 | `filehub` | 同上 | 同上 |
| 同步空间/0_收件箱 | `进子文件夹`（排在 filehub 下面） | Kind is Folder | Run rules on folder contents |

- 系统设置 → 隐私与安全性 → 完全磁盘访问权限里，Hazel 必须是打开的（已开）。
- **已知的坑**：新添加监控文件夹后，Hazel 的后台助手 HazelHelper 可能一直认不到这个文件夹，日志里反复出现 `Cannot find folder with id`。重新打开 Hazel 主窗口没用，要重启后台助手：
  ```bash
  launchctl kickstart -k gui/$(id -u)/86Z3GCJ4MF.com.noodlesoft.HazelHelper
  ```
- Hazel 只在文件夹有变动时重新检查，所以"满 3 天""满 7 天"到点后，最晚要等到这个文件夹下一次有变动时才处理。想立刻全部处理一遍，可以手动运行：
  ```bash
  /usr/bin/python3 ~/script/filehub/filehub.py tick
  ```
- Hazel 的规则文件是私有二进制格式（`~/Library/Application Support/Hazel/*.hazelrules`），AI 没法直接代写，只能在 Hazel 界面里配置。

## 八、脚本 filehub

位置：`~/script/filehub/`（只在这台 Mac 上，不在同步空间里）

| 文件 | 用途 |
|---|---|
| `filehub.py` | 全部规则 |
| `config.json` | `sweep_days`、`inbox_days` |
| `README.md` | 操作说明（比本文简短） |
| `迁移/` | 这次整理用过的迁移脚本、计划和撤销日志 |

命令：

```bash
filehub.py due FILE        # Hazel 条件：现在该处理返回 0，否则返回 1，不移动文件
filehub.py handle FILE     # Hazel 动作：有标签就路由；收件箱过期就进废纸篓；其余收进收件箱
filehub.py tick            # 一次处理桌面、下载、收件箱（手动补跑用）
filehub.py route FILE      # 只按标签路由
filehub.py sweep FILE      # 只收进收件箱
filehub.py has-route FILE  # 有路由标签返回 0
filehub.py undo LOG.tsv    # 按日志倒序撤销；撤销后日志改名为 .已撤销-时间
```

- 统一用 `/usr/bin/python3` 运行（系统自带的 Python 3.9，不依赖 Homebrew 的 Python）。
- 分辨率用 `/opt/homebrew/bin/ffprobe` 读取，读不到时退回 Spotlight 的 `mdls`。
- 运行日志在 `~/Library/Logs/filehub/filehub.log`。每次移动、每条通知都有记录，格式是：时间、动作、原路径、新路径。
- 在临时目录里测试、不碰真实文件时，用这些环境变量：`FILEHUB_ROOT`（代替同步空间）、`FILEHUB_WATCH`（冒号分隔的监控文件夹）、`FILEHUB_TRASH`、`FILEHUB_LOG_DIR`、`FILEHUB_CONFIG`。
- 旧的 Hazel 脚本在 `~/script/hazel/`，已经弃用。它要求下载时就手动给文件名加项目码，太累，所以没用起来。

## 十二、没反应时的排查顺序

1. 标签开头是不是项目代码（`LYX`、`RQ`、`QRFB`），有没有打错。
2. 用脚本直接判断：`/usr/bin/python3 ~/script/filehub/filehub.py due "<文件路径>"; echo $?`。返回 0 说明脚本认为该处理，问题在 Hazel；返回 1 说明问题在标签或时间还没到。
3. 看 Hazel 日志 `~/Library/Logs/Hazel/Hazel.log`：有没有 `Processing folder Desktop`、`Rule filehub matched`，有没有 `Cannot find folder`。有问题就重启后台助手（见第七节）。
4. 看 `~/Library/Logs/filehub/filehub.log`，里面的通知会写明原因。
