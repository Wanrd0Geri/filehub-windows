# filehub：桌面 → 项目的自动收纳

Hazel 负责监控和触发，规则全部在 `filehub.py` 里。要改规则就改这个脚本（或让 Claude 改）。

## 你要做的

- 能用的文件：右键 →「标签…」→ 输入标签名 → 回车。Hazel 会把它改好名字、放进项目。
- 其余文件：不用管。3 天没动会自动进 `同步空间/0_收件箱/<图片|视频|其他>/<进收件箱那天>/`（按扩展名分；文件夹一律进「其他」），在收件箱放满 3 天后整批进废纸篓。
- 收件箱里的文件也能打标签送走。

## 标签：项目代码 + 目的地，连着写

项目代码：临渊行 `LYX`、肉球 `RQ`、前任们 `QRFB`。**没有项目代码开头的标签一律不管**（颜色标签、你自己的分类标签都不受影响），只有 `通用测试` 例外。

## 命名规则

- 日期-序号：文件名里有日期就用（即梦自带），否则用文件创建日期；序号 = 同一场/同一资产当天第几个。
- 文件名里已有 `260922-2` 的（例如超分出来的同一条）沿用原日期序号，只补分辨率。
- 镜号：写在标签里（`LYXE02S10C25`），或把文件名改成 `25`／`C25` 再打 `LYXE02S10`。
- 分辨率只加在视频上，按画面宽度：<1200 → 480p，<1700 → 720p，<3000 → 1080p，其余 4K。

## Hazel 配置（4 个文件夹、6 条规则）

所有判断都在脚本里，Hazel 只负责触发。要复制粘贴的只有两行：

- 条件：`/usr/bin/python3 "$HOME/script/filehub/filehub.py" due "$1"`
- 动作：`/usr/bin/python3 "$HOME/script/filehub/filehub.py" handle "$1"`

**规则「filehub」**（桌面、下载、收件箱三处都加这一条）
- If **all** of the following conditions are met：`Passes shell script` → embedded script，Shell 选 `/bin/zsh`，粘贴「条件」那行
- Do the following：`Run shell script` → embedded script，Shell 选 `/bin/zsh`，粘贴「动作」那行

**规则「进子文件夹」**（加在 `同步空间/0_收件箱`，排在最后）
- If **all**：`Kind` is `Folder`；`Date Last Matched` is not in the last `10` minutes（让 Hazel 每 10 分钟重看一遍，「到期」才能按时生效；代价是收件箱里打标签最多等 10 分钟）
- Do：`Run rules on folder contents`

**同步空间**（第 4 个文件夹，加 `~/同步空间` 本身）
- 规则「filehub」：和上面一模一样，照抄那两行
- 规则「进子文件夹」：If **all**：`Kind` is `Folder`，**再加一条** `Name` is not `0_收件箱`（收件箱已单独监控，避免处理两遍）；Do：`Run rules on folder contents`

脚本的判断：
- 桌面、下载：有路由标签 → 改名进项目；3 天没动 → 进 `0_收件箱/<图片|视频|其他>/<进收件箱那天>/`；`~$` 锁文件、网盘残留 → 废纸篓。
- 收件箱：有路由标签 → 改名进项目；日期文件夹创建满 3 天 → 整个移到废纸篓（改名为 `收件箱_视频_260923`），并弹通知。
- 天数可在 `config.json` 里改：`sweep_days`（默认 3）、`inbox_days`（现为 3）。

**规则「定时」**（桌面、下载各加一条，排在 filehub 下面）——Hazel 不会为脚本条件定时回来看，要靠它自己的日期条件叫醒
- If **all**：`Date Last Modified` is not in the last `3` days；`Date Added` is not in the last `3` days
- Do：`Run shell script` → embedded script，Shell 选 `/bin/zsh`，粘贴「动作」那行

**规则「到期」**（只加在 `同步空间/0_收件箱`，排在 filehub 和「进子文件夹」之间）
- If **all**：`Kind` is `Folder`；`Name` matches `######`（6 个 #，代表 6 位数字）；`Date Created` is not in the last `3` days
- Do：`Run shell script` → 同上，粘贴「动作」那行

天数以脚本为准（config.json），Hazel 的日期条件只负责按时叫醒；即使叫早了，脚本也会再判断一次。

说明：Hazel 在文件夹有变动时会重新检查。「满 3 天」到点后由上面的日期条件叫醒 Hazel 处理（桌面、下载按文件排期，收件箱每 10 分钟看一次）。想立刻全部处理一遍，可以手动运行：`/usr/bin/python3 ~/script/filehub/filehub.py tick`

## 自动做的几件小事

- **网盘不认的名字**：`\ / : * ? " < > |` 换成全角（`|` → `｜`），`𝟖𝐊` 这类花体字母数字转成普通的 `8K`，emoji 去掉，文件和文件夹都改。桌面、下载、收件箱、整个同步空间都会改（同步空间那条 Hazel 规则负责直接拖进项目的文件）。补漏：`/usr/bin/python3 ~/script/filehub/filehub.py fixnames ~/同步空间`
- **进项目前查重**：打了标签的文件，如果项目里已经有内容一模一样的（名字不同也算），就不再放第二份，直接进废纸篓，弹通知告诉你已有的是哪个。
- **收件箱清空文件夹**：收件箱里的东西被送走后，留下的空文件夹自动删掉（最多删到日期文件夹）。
- **项目里也能打标签**：同步空间里的文件打路由标签，一样会被送到对应位置；项目里的文件不会被扫进收件箱。

## 日志与撤销

- 每次移动都记在 `~/Library/Logs/filehub/filehub.log`（时间、动作、原路径、新路径）。
- 迁移批次的日志在 `迁移/`；撤销整批：`/usr/bin/python3 filehub.py undo 迁移/<批次>.tsv`

## 新项目

复制 `同步空间/_模板/项目` 到 `同步空间/1_异类北京/项目/`，改名为 `YYMMDD_代码_名称`。

## 项目里的下划线文件夹

迁移时从旧 `备份/`、`预演/`、`三维/` 转来，新文件不会自动进这些地方：

- `_旧版/`：旧的备份版本
- `_预演/`：白模预演（第二集第 10 场）
- `_工程/`：三维、工程文件
- `3_制作/音乐/`：肉球的配乐（保留原名）

迁移对照表（每个文件的旧路径 → 新路径）在 `迁移/260923_第二批.tsv`。

## 打了标签没反应时

1. 标签开头是不是项目代码（`LYX`、`RQ`、`QRFB`），有没有打错。
2. 看 Hazel 日志 `~/Library/Logs/Hazel/Hazel.log`。如果出现 `Cannot find folder with id`，或者很久没有 `Processing folder Desktop`，就重启 Hazel 的后台助手：
   `launchctl kickstart -k gui/$(id -u)/86Z3GCJ4MF.com.noodlesoft.HazelHelper`
3. 新加文件夹或改了规则后 Hazel 不动：在 Hazel 里选中该文件夹 → Action（…）→ Run Rules Now。原因是 Hazel 只重新检查有变动的文件，规则改了它不一定重扫。
4. 看 filehub 自己的日志 `~/Library/Logs/filehub/filehub.log`，里面有每次移动和每条通知的原因。
