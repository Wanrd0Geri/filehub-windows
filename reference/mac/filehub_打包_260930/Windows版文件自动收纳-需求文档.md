# Windows 版文件自动收纳（filehub）需求文档

> 用法：把这份文档，连同 Mac 上 `~/script/filehub/` 整个文件夹（`filehub.py`、`README.md`、`config.json`）一起交给 Windows 电脑上的 AI（Claude Code 或 Codex），对它说：
>
> 「按这份需求文档，在这台 Windows 电脑上做一个 filehub 的 Windows 版。命名规则全部照搬 filehub.py，不要自己重新设计。先读完文档和 filehub.py，列出你的实施计划和要我确认的问题，我确认后再动手。」

---

## 第一部分：Mac 上现在是怎么用的（背景）

### 1. 一句话

所有东西先放桌面。**想要的文件打一个标签，它就自动改名、放进项目文件夹；不想要的什么都不用做，3 天后自动进收件箱，再 3 天自动进废纸篓。**

### 2. 分工

- **Hazel**（Mac 上的付费软件）只负责"盯着文件夹，有动静或到点了就叫一声"。
- **filehub.py**（Python 脚本，约 780 行）负责所有判断：这个文件该去哪、叫什么名字、该不该清理。
- 所以要做 Windows 版，**真正要移植的是 filehub.py 的逻辑，Hazel 只需要找一个 Windows 上的"叫醒"替代品。**

### 3. 盯着的文件夹

| 文件夹 | 做什么 |
|---|---|
| 桌面、下载 | 有路由标签 → 改名进项目；3 天没动 → 进收件箱；`~$` 开头的锁文件、`.baiduyun.uploading.cfg` 网盘残留 → 废纸篓 |
| `同步空间/0_收件箱` | 有路由标签 → 改名进项目；日期文件夹建好满 3 天 → 整个进废纸篓（改名 `收件箱_视频_260923`），弹通知 |
| `同步空间`（整个） | 百度网盘不认的文件名自动改掉；项目里的文件也能打标签送走；**项目里的东西绝不会被扫进收件箱** |

收件箱的结构：`0_收件箱/<图片|视频|其他>/<进收件箱那天，如 260930>/`。按扩展名分类，文件夹一律算"其他"。

天数在 `config.json` 里：`sweep_days: 3`（桌面进收件箱）、`inbox_days: 3`（收件箱进废纸篓）。

### 4. 标签怎么写（路由规则）

标签 = **项目代码 + 目的地**，连着写。项目代码：临渊行 `LYX`、肉球 `RQ`、前任们 `QRFB`（从 `同步空间/*/项目/YYMMDD_代码_名称` 文件夹名自动读取，不写死）。**不以项目代码开头的标签一律不管**，唯一例外是 `通用测试`。

| 标签 | 去向 | 文件名 |
|---|---|---|
| `LYX020822`（集 02 场 08 镜 22） | `3_制作/E02/S08/` | 视频：`02_08_22_01_20260926PM_1080p.mp4`；图片：`E02S08_C022_260926-1.png` |
| `LYX020815A`（插入镜头） | 同上 | `02_08_15A_01_…` |
| `LYX020815+20`（两镜合一条） | 同上 | 复制成两份：`…_15_…` 和 `…_20_…`（视频组规范要求） |
| `LYX020815+16+17`（三镜及以上） | 同上 | 只留 `…_15_…` 母文件，弹通知提醒告诉制片 |
| `LYX0208105` | 同上 | 镜号过百写 3 位：`02_08_105_01_…` |
| `LYXE02S08C22白模`（老写法，需要带备注时用） | 同上 | `02_08_22_03_20260926PM_白模_1080p.mp4` |
| `LYXPV决战` | `3_制作/PV/` | `PV_决战_260923-1_1080p.mp4` |
| `LYX苏云`、`LYX苏云法相`、`LYX破败庠序` | 已有资产文件夹，如 `1_设定/角色/苏云/` | `苏云_法相_260923-1.png`（资产名在标签任何位置都能认出，其余字当备注） |
| `LYX角色劫灰怪`（`场景`、`道具` 同理） | 新建资产文件夹 | `劫灰怪_260923-1.png` |
| `LYX成片E01` | `4_交付/` | `E01_成片_260923-1_4K.mp4` |
| `LYX剧本` / `LYX甲方` / `LYX参考` | `2_剧本分镜/` / `0_甲方/` / `_参考/` | 保留原名 |
| `LYX测试` / `通用测试` | `_测试/<日期>/` / `2_资料库/技术测试/<日期>/` | 保留原名 |

细节规则（全部以 `filehub.py` 为准，这里只列要点）：

- **集场镜视频**按视频组《视频素材命名规范》：`集_场_镜_版本_YYYYMMDDAM|PM[_备注]_分辨率`。版本号 = 同一镜头每进来一条 +1，跨天接着数；日期和 AM/PM 取**文件创建时间**（即梦下载那一刻）。视频必须有镜号（标签里写，或文件名本身是 `22.mp4`、`C15A.mp4`），没有就不动并提醒。
- **其他文件**：`前缀_[C镜号]_[备注]_YYMMDD-序号[_分辨率]`。文件名里已有 `260922-2` 就沿用；序号 = 同一目的地当天第几个。标签没写备注、而文件名已是标准名的，保留原备注。
- **分辨率**只加在视频上，用 ffprobe 读画面宽度：<1200 → 480p，<1700 → 720p，<3000 → 1080p，其余 4K。
- **查重**：进项目前按文件内容比对（先比大小再比哈希），项目里已有一模一样的就不放第二份，进废纸篓并提醒"已有的是哪个"。合镜复制出来的那份不查重。
- **标签写错**：文件不动，弹通知说明原因；同一个文件同一个标签只提醒一次。改对后自动重新处理。
- **一个文件只能有一个路由标签**，多个就不动并提醒。路由成功后删掉这个标签，其他标签（颜色等）保留。
- **百度网盘文件名**：`\ / : * ? " < > |` 换全角（`|` → `｜`），`𝟖𝐊` 这类花体字母数字转普通 `8K`，emoji 去掉。长文件名、结尾 `...` 网盘能同步，不截断。
- **收件箱送走东西后**，留下的空文件夹自动删掉（最多删到日期文件夹）。
- **每次移动都写日志**（时间、动作、原路径、新路径），支持按日志批量撤销（`undo`）。

## 第二部分：Windows 版需求

### 5. 目标

在 Windows 电脑上达到和 Mac 一样的体验：**文件先放桌面，要的一步送进项目并自动按规范命名，不要的自动清理。**两台电脑用同一套命名规则，放进同一个百度网盘同步空间，结果必须一模一样。

### 6. 最重要的三条原则

1. **不要重新发明规则。**命名和路由逻辑直接移植 `filehub.py`，最好是一份代码两边共用：把和系统有关的部分（标签、通知、废纸篓、创建时间、ffprobe 路径）抽成"平台层"，Mac 和 Windows 各写一份，其余全部共用。以后改规则只改一处。
2. **不要做一个通用的"Windows 版 Hazel"。**我们只需要这一套收纳流程，不需要规则编辑器、图形化条件设置这些。
3. **所有操作可撤销。**删除一律进回收站，不直接删；每次移动写日志。

### 7. Windows 上和 Mac 不一样、需要重新设计的地方

| 事项 | Mac 现在 | Windows 需要解决 |
|---|---|---|
| **怎么"打标签"** | Finder 标签（右键 → 标签…），存在文件扩展属性里 | Windows 资源管理器**没有通用的文件标签**（mp4、png 大多不支持"标记"）。建议：**右键菜单加一项「送进项目…」**，弹一个输入框，输入 `LYX020822` 回车就立刻处理；支持多选文件。请 AI 评估并给出方案 |
| **谁来"叫醒"** | Hazel | 建议 Windows 任务计划程序：开机登录时运行一次 + 每 10 分钟运行一次 `tick`（清理桌面、下载、收件箱）。右键菜单那条路是即时处理，不依赖定时 |
| **废纸篓** | `~/.Trash` | 回收站（例如用 Python 的 `send2trash`），能从回收站还原 |
| **通知** | macOS 通知中心 | Windows 通知（右下角弹窗） |
| **文件创建时间** | `st_birthtime` | Windows 的创建时间（注意：从网盘同步下来的文件，创建时间是同步那一刻，不是生成那一刻） |
| **ffprobe** | `/opt/homebrew/bin/ffprobe` | 需要安装 ffmpeg（如 `winget install ffmpeg`），路径写进配置 |
| **路径** | `~/同步空间`、`~/Desktop`、`~/Downloads` | 同步空间在 Windows 上的实际位置写进配置（如 `D:\同步空间`）；桌面、下载用系统默认位置 |
| **长路径、中文** | 无问题 | Windows 默认路径长度上限 260 字符，项目层级深 + 中文长文件名可能超限，需要处理（开启长路径支持或检测后提醒） |
| **非法字符** | 需要换全角 | Windows 本身就不允许这些字符，但花体字、emoji 仍要处理，规则保持一致 |
| **"满 3 天没动"** | 取创建、修改、放进文件夹三者中最晚的时间 | Windows 没有"放进文件夹的时间"，用创建和修改时间中较晚的那个 |

### 8. 两台电脑同时运行的冲突（必须处理）

两台电脑通过百度网盘共享同一个 `同步空间`，如果两边都去清理同一个收件箱、都去改同一批文件名，会出现重复处理和同步冲突。要求：

- **同步空间里的"全局任务"只由一台电脑做**：收件箱到期清理、整个同步空间的文件名修正。默认由 Mac 做，Windows 版这两项默认关闭（配置里有开关）。
- **Windows 只管自己的桌面和下载**：路由进项目、3 天没动的扫进收件箱（进收件箱那天的日期文件夹两边共用，没关系）。
- **版本号可能撞车**：两台电脑几乎同时往同一个镜头放视频时，可能都算出 `_03`。发现目标文件已存在就顺延（`_04`），不能覆盖。团队本来就规定"同一场由同一人命名"，这种情况很少，但程序不能出错。

### 9. 配置

一个 `config.json`（和 Mac 字段保持一致，Windows 专用的另加）：

- `sweep_days`：桌面、下载多少天没动进收件箱（3）
- `inbox_days`：收件箱多少天进回收站（3）
- `sync_root`：同步空间路径
- `watch`：要管的文件夹（默认桌面、下载）
- `ffprobe`：ffprobe 路径
- `global_jobs`：是否执行收件箱清理和全局改名（Windows 默认 `false`）

### 10. 验收标准（AI 做完要逐条演示给我看）

在一个**测试用的假同步空间**里跑，不碰真实项目：

1. 桌面上一个视频，右键「送进项目…」输入 `LYX020822` → 出现在 `3_制作/E02/S08/`，名字是 `02_08_22_01_<日期AM/PM>_1080p.mp4`。再送一条同镜头 → `_02`。
2. `LYX020815+20` → 生成两份；`LYX020815+16+17` → 只留一份并弹通知。
3. 图片输入 `LYX020822` → `E02S08_C022_<日期>-1.png`。
4. `LYX苏云法相`、`LYX破败庠序`、`LYX角色新角色`、`LYXPV决战` 都进对的地方、名字对。
5. 输入写错的代码（如 `LYX不存在`）→ 文件不动，弹一次提醒。
6. 项目里已有内容相同的文件 → 不放第二份，进回收站，提醒已有的是哪个。
7. 文件名带 `|`、`𝟖𝐊`、emoji → 自动改好。
8. 桌面一个 3 天前的文件 → 定时任务跑过后进 `0_收件箱/<类别>/<今天>/`；收件箱里 3 天前的日期文件夹 → 进回收站（打开 `global_jobs` 时）。
9. 日志里每一步都有记录，`undo` 能把一批操作撤回。
10. **同一批文件在 Mac 和 Windows 上处理，得到的文件名完全一样**（可以准备几个样本，两边各跑一次对比）。

### 11. 交付物

- Windows 版程序（建议仍是 Python，和 Mac 共用核心逻辑）
- 一键安装脚本：装依赖、注册右键菜单、建任务计划
- 一键卸载脚本：撤掉右键菜单和任务计划
- 一份中文使用说明（像 Mac 的 README 一样，写给不懂编程的人看）

### 12. 不在这次范围内

- 图形界面的规则编辑器
- 修改现有命名规则（规则只在 Mac 的 `filehub.py` 里改，Windows 跟随）
- 处理项目里已有的旧文件（已有文件不改名）
